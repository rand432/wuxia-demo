# 批次 25 交付 · 首次动作长帧与帧时间记录（P1）

对应交接：`docs/交接_DeepSeek战斗界面工程任务.md` 第二十五批。

## 1. 方法

新增 `tools/first_action_probe.gd`：固定种子 20261116、450×800、同一画面设置，每个动作前后记录实际时间戳与当帧状态；同一场景在**新进程**跑 6 次（首批 3 次 + 验证 3 次）。

动作时间线：挑战匪首（3s）→ 首次抽卡开/关（5/6s）→ 首次请神开/关（7/8s）→ 首领进场（9s）→ 首领技能（12s）→ 结算切入（15s）。

长帧定义：帧间隔 >33.3ms；记录 `t / ms / action / live / fx / fx_pool`。

- 结算切入 49.7–58.8ms **6/6 稳定复现**，是唯一稳定热点

## 3. 结算热点定位

对 `ResultView.present()` 分段计时（`fa_rt5.log`）：

| 段 | 累计 | 增量 |
|---|---|---|
| `Aud.sfx` | 0.6ms | 0.6 |
| 结局 CG + 遮罩 | 20.9ms | 20.3 |
| 面板底图/内容框 | 40.5ms | 19.6 |
| 六行数据 + 按钮 | 45.8ms | 5.3 |
| 入场动效 | 47.3ms | 1.5 |

主要耗时在首次使用结局面板/CG 纹理时的解码与上传。尝试把 `ending_win/lose`、`panel_win/lose` 提前 `load()`、提前播放 win/lose 音效、提前生成结果特效，三次复测 `present` 仍在 47–53ms，无改善，相关试验代码已回退。

该长帧发生在 `_end_run` 的 **0.3s 顿帧 + 0.5s 闪白**之内，结算界面在顿帧结束后才完成布局，属于刻意定格式的窗口内，玩家看不到卡顿；因此本轮不改结算结构，只留证据与结论。
