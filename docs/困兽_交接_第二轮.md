### 3.1 新增的两处架构（**下一轮先看懂这个**）

**① 一条内容"锁没锁"＝两条线合起来看**（`kushou_v2.gd`）

```gdscript
func _all_grants() -> Array     # 惰性建一次：UNLOCKS（存档）＋ STAGES 的 3 项首通奖励
func _stage_rewards(s) -> Array # 一关的 3 项奖励（第 1 项老字段 ＋ un2/un3）
func _grant_id(r) -> String     # 奖励 → u_set_xxx / u_part_xxx / u_trea_xxx / u_pet_xxx
```

`_locked_sets / _partner_locked / _trea_locked / _pet_locked / _mate_is_unlocked` **全部走 `_all_grants()`**。

> ⚠ 上一版的坑：这几处**只读 UNLOCKS** —— `_stage_clear()` 写进去的 `u_set_panshixin` 之类
> **从来没人读**（关卡奖励等于是摆设），而 4 位同时在存档表里的伙伴被"顺手"白送
> （打 1-3 就白得 1200 文钱的白婆婆）。现在两条线各给各的，**一条都不重合**。

**② 一关一只 boss**（`STAGES` 的 `boss`/`btier` ＋ 战场的 `stage_boss`）

- 16 关 ↔ `BOSS_TIER` 16 只，一条条对着排；这一关**所有 boss 波（10/15/20/25/30/35）都是它**
- 无尽模式不点名 → 战场按波数涨阶、阶内随机
- ⚠ `spawn_pack("boss")` 那条分支是**死代码**（没人调）；屏幕上的"boss 挑战"走 `spawn_challenge(4)`，
  刷的是**挑战大怪**（`kind="chal"` 但 `boss=true`），不是 `BOSS_TIER` 里的 boss —— 别搞混

### 3.5 用户报的「强化时血量变满」—— 修好了，顺带查出一个更大的

#### ① 属性同步 = 满血（**v18i 已修**）

用户："有问题 强化时 血量变满了"。根因在战场 `setup()`：

```gdscript
hero["hp"] = float(hero["hp_max"])      # ← 无条件补满（不是只在开局调！）
```

`setup()` 被外壳 `_sync_battle_stats()` 调，而后者有 **30 来个调用点**
（抽卡成套 / 升级 / 属性加点 / 装备 / 宝物 / 黑市 / 宠物 / 进化 / 打坐每秒 / 强化…）
→ "改任何属性 = 当场满血"；更狠的是**血 0 倒下时同步一次会被复活成满血**。

修法：血按**比例**跟着上限走（上限涨多少 %，当前血涨同样 %；残血比例不变、0 还是 0）。

| 探针 k966 | 修前 | 修后 |
|---|---|---|
| 残血 40% → 点一次［强化］ | 100% | **40%** |
| 残血 40% → 只同步一次 stats | 100% | **40%** |
| 残血 40% → 升到 Lv13（上限 264→835） | 100% | **40%**（334/835） |
| 血 0 → 同步一次 | 满血复活 | **0%** |
| 重开一局 / 浴血 | 100% / 50% | 100% / 50%（没动） |

探针 k967（1-1 自动打 60 秒、不做任何操作）：血 100% → 30 秒 72% → 50 秒 21% → 浴血一次 → 60 秒 29%。
**修之前这一整段基本是满血** —— 所以过去量到的"坦度"全是在这个隐形回复下量的，要重新评估。

#### ② 更大的一个：**外壳的波数从来没传给战场**（**还没修，等用户拍板**）

探针 k969 实测（1-1，把外壳推到第 10 波）：

```
外壳推到第 10 波：外壳 10 · 战场 1 · 怪血 34 · 定额 8      ← 战场还停在第 1 波
手动 set_wave(10) 之后：外壳 10 · 战场 10 · 怪血 165 · 定额 12   ← 手动一设才变
```

`_field.set_wave(_wave)` **只在 `open()` 里调过一次**（彼时 `_wave` = 1），波次推进处没有再调；
而战场所有成长都读自己的 `wave`：

| 受影响的东西 | 现在的实际值 | 设计值 |
|---|---|---|
| 怪血 `_foe_hp()` | 恒 **34** | 波10 165 · 波20 614 · 波35 4388 |
| 怪攻 `_foe_atk()` | 恒 4.5 | 按 `WAVE_ATK` 指数涨 |
| 难度系数 `diff_mul()` | 恒 **1.0** | 第 10 波起 ×1.5 |
| 每波定额 `_wave_quota_for()` | 恒 **8** | 波 26+ 到 20（v17x 写的封顶逻辑等于没生效） |
| boss 血量/攻击 | 恒**基础值**（`pow(WAVE_HP, wave-1)` = 1） | 随波放大 |
| 挑战怪爬升 `chal_hp_mul()` 等 | 恒 1.0 | 每波 +6%/+5%/+3%/+4% |
| 无尽模式最高波 `_best_wave` | **永远是 1** | 记最高波 |

⚠ 战场那边的注释写着"外壳直接把 wave 改掉，没有 set_wave 可挂"（v17x）—— **这个假设是错的**，
外壳从来没改过它。一行就能修（波次推进处补 `_field.set_wave(_wave)`），
但**修完整局难度会重排**（怪血从"恒 34"变成"波35 4388"），所以先问用户，不擅自改。

## 4. 踩过的坑（**必读，能省几小时**）

### 4.1 最严重：用 PowerShell 写源文件，把 `kushou_battle.gd` 写成了 1467 字节

- 原本 **5395 行 / 293KB**，被 `[System.IO.File]::WriteAllText()` 覆盖成 **28 行**

  `$T` 把 `$t` 覆盖了，写进去的是一个字符

- **教训**：**永远不要用 PowerShell / 脚本写 `res://` 下的源码。**
  只用 `write` / `edit`（它们校验 `old_string` 唯一性，写坏立刻发现）。
  **PowerShell 只用来读**（grep / 统计 / 跑 Godot / git）。
