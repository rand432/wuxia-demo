## 二、五个结构性问题（按严重度）

### P1 职责过载：一个 Control 干了七件事

`_ready`（:422）60 行里串行做了：加载美术缓存 → 建背景 → 建 HUD → 建战场并**实例化战斗内核**（:1156）→ 建卡组/底栏 → 预热抽卡图 → 建黑市/教学层 → 刷新数值 → 淡入。

`_process`（:3101）218 行里同时做：**关卡平衡**、波次推进、Boss 出场判定、血条刷新、技能/奇物/增益 tick、对象池回收、怪物 token 同步、Boss 蓄力/落点、特效回收。

结果：改任何一处都得读 9000 行上下文，且无法单独测试。

### P2 平衡逻辑塞在 UI 的每帧循环里

`:3144-3176` 直接按 `LevelState.current_level` 分支改 `_core.foe_vuln`：

- L2–4：按卡组组合给 6%/10%/15% 易伤
- L7：按技能总级给最多 30%
- L8：按装备 +值给最多 35%

这是**逐关补丁式平衡**，以后每加一关都要改 UI 文件，而且每帧重算一遍（虽然有分支保护，仍属浪费）。

### P3 没有事件边界：UI 与内核双向耦合

`_core.` 出现 571 次；`_build_field` 里连了约 20 个内核 signal（:1176-1196）。反过来内核也可能直接读 UI 状态。后果：

- UI 换皮/拆分必须动内核
- 内核改动会无声打断 UI（没有接口契约）
- 单个模块无法在审计里独立实例化

### P4 版式全硬编码

572 个 `Vector2`、119 个 `Rect2` 直接写死在函数里（如 `_build_hud`、`_build_bottom`）。改 720×1280 版式只能全局搜数字，且没有「设计令牌」层。

### P5 资源路径分散

`_foe_art_path` 本身只有 2 行，但全文件有 **82 处 `res://` 字面量（57 个唯一路径）** 和 **49 处 `preload()`**：
背景图、怪物立绘、怪物帧、围观群众、特效帧、龙头、奇物图标、角色帧……各写各的。
没有「资源路径表」这一层，换素材/查缺图得全文件搜。

## 三、拆分建议（四批，风险从低到高）

### 批次 1：低风险纯搬移（建议现在就做）

| # | 抽什么 | 去处 | 预计行数 | 风险 |
|---|---|---|---|---|
| 1 ✅ | 13 个美术常量 + `foe_art_path()` 路径表（含 30 处引用） | `kushou/battle_art.gd` | 迁移 55 行 | 已完成 |
| 2 | `_fill_result` + 结算相关 | `kushou/result_view.gd` | ~250 | 低（已在上一轮修过） |
| 3 ✅ | `_process` 里的 L2–10 平衡分支 | `kushou/balance_rules.gd` 的 `level_vuln()` | 迁移 33 行 | 已完成 |

批次 1 完成后的收益：battle_ui 少 600 行；改平衡不再碰 UI；立绘缺图排查有唯一入口。

### 批次 2：抽 UI 面板（中风险，3–5 天）

4. 卡组/抽卡（`DrawCard`、`_roll_draw`、`_init_cards`）→ `battle_cards_view.gd`
5. 宝物 / 强化 / 奇物三个面板（分段注释已经切好，:158 / :192 / :1582）→ 各自模块

### 批次 3：战场渲染（中高风险，约 5 天）

6. `_build_field` / `_make_foe_token` / `_step_minions` / 特效池 → `battle_field_view.gd`

### 批次 4：不建议现在做

7. `_cast_skill` / `_apply_combo` 迁进内核——要动战斗规则，88 个用例里一大半覆盖这块，回归成本最高，收益最小。

## 四、明确不建议的两件事

- **全量重写**：现有 88 个用例测的是行为，不是结构；重写等于把验证网推倒重来。
- **引入全局 EventBus**：内核已经有 ~20 个 signal，再加一层总线只是换个地方耦合，不解决问题。

## 五、每批的验证方式

1. 语法门禁：`godot --headless --check-only --script`
2. 行为回归：搬动哪块就跑对应子集（`battle_lifecycle`、`result_panel`、`result_freeze`、`treasure_flow`、`outgame_loop`、`skill_boundary`…）
3. 视觉回归：改动 UI 的批次，用探针截同场景前后对比图
4. 最终全量 88 项
