## 三、遗留与风险（GPT 排期时要考虑）

1. 两按钮仍用审计的 `pressed.emit()` 验证，**没有真实鼠标点击用例**
2. 结算延迟显示期间释放场景只有 tween 绑定保护，**没有专门用例**
3. `DrawCard`（约 75 行）与 `AugCard`（约 1,100 行）仍留在 `battle_ui.gd`，只通过 factory 注入
4. 宝物/强化/奇物三个面板外观重复实现，**未抽公共基类**
5. `battle_ui.gd` 里仍有 `_process` 194 行、`_build_field` 179 行等大函数（下一步可继续拆）
6. 工作区可能有并行同事改动（首领素材、卡框、`project.godot` 拉伸模式），提交时不要混入

## 四、如何给 DeepSeek 下任务（模板）

```markdown
### 任务：<一句话目标>
- 范围：<要改的文件/模块；不要动的部分>
- 验收：<可执行判定，如"88 项回归全绿"、"L7 通关 ≤320s">
- 约束：<不能改的接口/资源/行为>
- 交付：<差异说明、回归结果、截图路径、遗留问题>
- 优先级：P0/P1/P2
```

它的固定工作方式：先读代码跑基线 → 先报方案再动手 → 小步迁移 → 指定用例 + 全量回归 → 留证据文档 → 可回滚提交。
