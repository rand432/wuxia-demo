## 0. 一句话现状

外壳（界面·养成·局外系统）＋ 战场（战斗·怪物·特效）两个脚本，**能跑、能玩、局外系统齐全**，
还差几处**数值收尾**和**两个半成品功能**（见 §6）。

**用户是唯一决策人**，改动前最好先说方案；他更看重「实测数字 + 截图」而不是口头描述。

## 2. 架构速查

### 2.1 外壳 `kushou_v2.gd`
- 一个 `Control`，左侧圆钮列（抽卡/挑战/任务/卡组）＋ 右侧（存档/成就/黑市/玉壶）
- 战场是子节点：`_field.position = Vector2(8, 176)`，`Rect2(8,176,704,704)`
- 弹窗统一走 `_open_large(kind)` / `_close_popup()`，`_fill_popup(p, y, sz)` 按 kind 分派
- 大弹窗清单（`_is_large`）：卡组/技能/装备/关卡/角色/存档/成就/黑市/宝物三选一/抽卡…

### 2.2 关键状态（外壳）
| 变量 | 含义 |
|---|---|
| `_money` / `_crystal` / `_kills` | 文钱（＝用户口中的「银两」）/ 灵晶 / 杀敌数 |
| `_wave` / `_wave_max` | 当前波 / 本关波数上限 |
| `_lv` / `_exp` / `_attr_pts` / `_skill_pts` | 等级/经验/属性点/技能点 |
| `_extra` | **所有加成的大杂烩字典**（卡组/宝物/成就/宠物都往这写）|
| `_attr` / `_grow_inherit` / `_grow_card` | 三属性来源 |
| `_sets_done` / `_card_have` / `_deck_cards` | 卡组成型 / 已有卡 / 十格占位 |
| `_unlocked` / `_stage_done` / `_pet_star` / `_pet_kind` | 局外进度（存 meta）|

### 2.3 战场 `kushou_battle.gd`
- `hero` 字典：战斗属性都在这（`atk/hp/hp_max/crit/cut/dmg_all/...`）
- `foes` 数组：每只怪一个字典（`hp/x/y/kind/boss/para/dot/...`）
- `_apply_dmg(f, amount, dtype)`：**怪物受伤的唯一入口**（物理吃 `hp_max×2%` 的防御折算）
- `hero_in_dmg(amount, dtype)`：**主角受伤的唯一入口**（减伤/格挡都在这）
- `_kill_foe(f)`：死亡结算（掉钱、连杀、成就计数、机制卡触发都在这）
- 敌人强度：`_foe_hp()` / `_foe_atk()` ＝ `BASE × WAVE^(波-1) × foe_mul`

## 4. 这次会话踩过的坑（**务必读，能省你几小时**）

### 4.1 编辑纪律（血的教训）
- **改一处 → 重读上下文 → 跑 `--check-only`**，绝不要凭行号批量盲改
- `read` 的 `old_string` 太短会**匹配多处**；用**3~5 行锚点**消歧
- 多个相同片段（如 `if key == "attr_all":`）在文件里出现多次，一次改错就会**吃掉下一段**
- 本会话因为"编辑吃行"返工过十几次，**每次都要立刻 `--check-only`**

### 4.2 GDScript 坑
- `var x := 动态调用()` 会**无法推断类型** → 写 `var x: float = ...`
- 字符串用 `substr`（**不是 `slice`**）
- 多语句 lambda 容易出问题 → 拆成具名函数
- 往 Node 上挂临时字段会报 `Invalid access to property`

### 4.3 逻辑坑（重要！）
1. **`_set_check()` 里 `_sync_battle_stats()` 在 match 之前调用** → 刚成套那套效果要等下次同步才生效。
   已在 match 之后补了第二次同步（v14a）✓
2. **`_wpn_sync()` 每帧覆盖 `_extra["wpn_arm/agi/wit"]`** → 往这里写属性是**死键**。
   已新开 `bonus_arm/agi/wit` 通道（`_attr_*()` 里读取）✓
3. **`kill_normal` 会被波次推进清零** → 探针别用它做停止条件（本会话在这里栽了三次）
4. **掉落是异步的**（怪死 → 掉地 → 飞向右上 → 入账），测量要等 ≥100 帧
5. `_credit_drop(kind, n)` 是**唯一入账口**，文钱在这里吃 `money_bonus`（聚宝盆/寻宝卡）**和随波数放大** `× (1 + 0.04×(波-1))`

### 6.7 §6.1 收益侧的实测数字（这一轮补上了，**还没调**）

**每只掉落（实测；`_credit_drop` 的 wave_mul = 1+0.04×(波-1)）**

| 来源 | 表值 | 实测（波15） |
|---|---|---|
| 普通怪 | 1~3 | **3.1**（波1 每只 2.0） |
| 钱怪 | 30~60 | **72.4** |
| 钱怪挑战 ×6 | 40~80 ×6 | **649**（波1 569 → 波30 760） |
| 晶怪挑战 ×3 | 8×3 | **24 灵晶**（**不随波放大**：灵晶那条路没有 wave_mul） |
| 宝物大怪 | 220 | **344** |

**每波普通怪收入（实测杀怪速度推的）**：波1 **100** · 波5 **116** · 波10 **137** · 波15 **123** · 波20 **118** · 波30 **79**
→ **越往后越穷**：怪血 ×1.12/波 比 掉落 ×1.04/波 涨得快；30 波时砍一只 3.27 秒、只值 4.3 文钱。

**一局（30 波）大致总账**：普通怪 ≈ 3.5k ＋ 钱怪挑战 ≈ 9.7k（70 秒一次、一局约 15 次）＋ 钱袋与其他 ≈ 2k ＝ **文钱 13~15k**；灵晶 ≈ 700~900。
**物价对照**：存档 26 项解锁合计 **18,050 文钱** → 一局多一点就能买空；抽卡 20 灵晶/张 → 一局能抽 35~45 次。

**结论 / 等用户拍板**：
1. 收益**够花、甚至偏松**——要更难就抬存档价格，或压钱袋（文钱袋 50 杀敌换 600 文钱 ≈ 12:1，是最大的一处杠杆）；
2. 掉落随波放大是**线性 1.04**，跟怪的指数成长不匹配 → 建议改 `1 + 0.04×(波-1) + 0.002×(波-1)²`：波30 每波从 79 回到 ~154，一局多约 620 文钱（对上面那本大账影响很小）；
3. 挑战收入**不随波放大**（`_on_chal_drop` 直接加账）——要不要跟掉落同一条曲线，也是个选择。
