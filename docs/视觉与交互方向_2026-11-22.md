# 视觉、交互与战斗表现方向

## 用户本轮明确调整

动画效果、点击反馈、弹窗表现、刷怪爽感、布局与流畅度优先；数据类问题降低优先级。此前存档保护仍保留，后续不再以不断增加数据回归数量代替可见体验改善。

交互和布局参考《咸鱼之王》《向僵尸开炮》，角色与立绘参考鸣潮仇远、崩坏星穹铁道、明日方舟精二。用户期望精致、AAA级品质目标：二次元角色审美，细致的人体/服装/材质与写实塑造，墨色渲染统一江湖气质。

**最新明确约束：战斗继续使用原Q版圆牌。精细立绘用于局外角色展示，不放进战斗替代圆牌。** 用户同时要求窗口和卡牌有略显Q弹的弹跳、回摆与落定感，并强调不能因动效卡顿；程序剑和临时特效需要优化或重绘。

鸣潮仇远[官方参考页](https://wutheringwaves.kurogames.com/jp/main/news/detail/3480)用于人物视觉对照。已有图片搜索仅能支持静态画面观察，尚未据实机录像逐帧提取两款小游戏的交互时序。

## 后续工作的顺序

1. 点击触感与窗口进出：短促按压、清晰回弹、轻量扩散、高低层级、弹出/收起时序。保持操作响应及时，减少同时发生的动效相互争夺注意力。
2. 战斗爽感：刷怪的入场节奏和群体层次、出手预备与命中反馈、普通/重击/暴击的强弱关系、击杀消散和连杀反馈，再处理大招演出。
3. 角色与场景视觉：先做可验收的角色样稿，确认面部、体态、服装层次、材质、光影与墨色比例，再扩展立绘和战斗形态。AAA是用户要求的品质目标，当前旧素材尚未达到该目标。
4. 数据排查仅处理阻碍体验、进度或保存的实际问题，其他数值核对后置。

- 新增shared/ui_motion.gd，共用按钮按下约65ms缩至96.5%，松开约180ms回弹，点击触发约320ms的金色边缘扩散。绘制变换与实际按钮点击区域分离，按在原区域边缘不会因视觉缩小丢失点击；按钮回调仍即时执行。

- 反馈空闲时不逐帧运行；重复按压替换本按钮旧缓动，切页后不继续启动新缓动。

## 第二批：入场、命中、消散与连斩

现有敌人TokenActor通常没有头像纹理，旧play_hit只给_sprite变色，圆牌及文字缺乏可见反馈；旧死亡连续闪烁并拖到1.05秒。本轮把表现作用到整个牌体：

- 敌人约260ms浮现、收放回弹，同批采用0～60ms的轻微错落；不改变刷怪实际时机、碰撞、寻敌或伤害。
- 命中约160ms沿受击方向短移并压缩回弹，重击/暴击加强；主角起手也有轻微蓄放。显示变换保留核心脚底坐标。
- 确认死亡即开始约380ms墨色碎线消散，不等核心移除对象才表现死亡；重复play_down不重置动画。回收复用清除入场、受击、透明度和死亡姿态，避免旧状态带到下一只敌人。
- 命中特效从脚底移到身体附近，数字增加冒出与减速上浮，重击数字采用深色字心和金色边缘，改善纸色背景上的可读性。
- 战斗外壳关闭核心重复的普攻数字和浅色连杀字，使用右上角清晰的连斩读数；核心独立入口仍保留原显示。技能/异常状态文字尚未全部统一，其他伤害入口的身体受击表现也需继续梳理。

`tools/preview_combat_motion.gd`录制真实核心自动攻击与击杀，得到300帧、30fps、10秒无声演示`.shots/combat_motion_preview.mp4`。受控构筑在隔离目录设攻击80、攻速2、暴击35%、气血2000和一级溅射，并安排演示敌群；日志记录29次真实击杀。它用于表现观察，不能代替自然关卡构筑或数值平衡结论。已查看实际入场/消散/伤害字/连斩帧，沿用现有角色与圆牌素材，精细人物立绘仍待制作。

定向检查attack_timing、attack_boundary、attack_crit、kill_once、battle_navigation、result_freeze均通过；kill_once仍有既有直接退出对象/资源提示，其他本轮定向日志无ERROR/WARNING。未重跑全部数据矩阵来代替动效验收。

桌面渲染压力复测：720×1280、60帧上限、GTX1050Ti、25只敌人、6技能、1召唤物、11次有效施法；6秒预热后采样15秒共901帧，平均16.65ms、P95 16.77ms、最大17.60ms、超过34ms为0次。记录`.shots/bench_after_combat_motion.log`。这仅证明本机短时场景表现，不代表移动端和长期战斗。

## 怪物出招的区分

怪物进入原出手周期的最后约160毫秒时，会短暂压身蓄力。近身攻击前扑并留挥击弧，弓手后坐并留下箭迹，法师抬身并放出紫色术光。箭迹和术光是即时攻击后的短残影，沿当前实际目标方向绘制。命中、预警、闪避和伤害时机仍由原战斗逻辑结算。表现列表最多24条，每条约180毫秒，无需为每次出手新建场景节点。

`tools/preview_combat_motion.gd -- --enemy-showcase`的隔离用例验证三种出手与蓄力、主角实际扣血，录制输出为`.shots/enemy_roles_preview.mp4`。普攻时序、受伤、敌人预警、回溯和战斗导航定向检查通过。桌面同一压力场景共901帧，P95 16.69ms、最大19.18ms，超过34ms为0次。记录`.shots/bench_enemy_roles.log`。当前是共用 Q 版角色原画的动作变化，后续角色专用逐帧动画仍需制作。
